# codex-night

Обёртка для длительных заданий Codex CLI. При подтверждённой ошибке capacity она ждёт и продолжает
тот же диалог. Работает с любым проектом, использует существующую авторизацию Codex и не меняет
глобальные настройки, модель или правила разрешений.

Есть два режима:

- **Интерактивный:** обычный Codex CLI в tmux. Можно писать уточнения прямо во время работы.
  После capacity отправляется продолжение в тот же процесс; CLI не перезапускается.
- **Пакетный:** `codex exec --json`, удобен для запуска без терминала. После capacity завершившийся
  процесс заменяется новым `codex exec resume` с точным session ID.

## Установка

Нужны Python 3.8+, установленный и авторизованный `codex`. Для интерактивного контроля также нужны
Linux с `/proc` и tmux. Проверено с Codex CLI 0.166.0; формат его журнала и composer может измениться
в следующих версиях. При несовпадении состояния контроль останавливает автоматический ввод.

```sh
git clone https://github.com/ssastrukovs/codex-night.git ~/.local/share/codex-night
mkdir -p ~/.local/bin
chmod +x ~/.local/share/codex-night/codex_night.py
ln -s ~/.local/share/codex-night/codex_night.py ~/.local/bin/codex-night
```

Добавьте `~/.local/bin` в PATH, если его там нет. Репозиторий приватный: для clone нужна ваша GitHub-авторизация.
Если утилита уже установлена в этот каталог, обновляйте существующую копию, не клонируйте поверх неё.
Сторонние Python-библиотеки не требуются.

## Интерактивная работа

Запускайте внутри tmux:

```sh
codex-night --interactive -C ~/project --approve-for-me 'Выполни задание и необходимые проверки'
```

Продолжить сохранённый диалог:

```sh
codex-night --interactive -C ~/project --resume UUID_ДИАЛОГА --approve-for-me
```

Модель и reasoning можно задать явно:

```sh
codex-night --interactive -C ~/project --approve-for-me \
  -m gpt-6.1-sol -c 'model_reasoning_effort="xhigh"' --prompt-file ~/night-task.txt
```

Это настоящий Codex CLI с сохранением scrollback, а не просмотрщик логов. Enter во время работы передаёт
уточнение в текущий ход, Tab ставит его на следующий ход. Для уточнений не нужно закрывать CLI и делать resume.

### Уже открытый CLI

Контроль capacity можно подключить к обычному Codex TUI, не перезапуская его. Из другого терминала
найдите нужную панель и укажите её явно:

```sh
tmux list-panes -a -F '#{pane_id} #{pane_current_command}'
codex-night --watch -C ~/project --pane %3 --resume UUID_ДИАЛОГА
```

`--watch` не запускает второй CLI и не меняет его модель, sandbox или разрешения. Переданный `-C`
должен совпадать с workspace открытого TUI. Если session ID не указан, он определяется по его журналу.
Это только контроль существующего процесса: workspace/session locks остаются у запустившей его
обёртки, а отдельный process lock защищает от второго watcher. Ctrl+C в терминале наблюдения останавливает
только наблюдение. Если закрыт или заменён сам TUI, автоматический ввод прекращается.

## Пакетный запуск

```sh
codex-night -C ~/project --approve-for-me 'Текст задания'
codex-night -C ~/project --approve-for-me --prompt-file ~/night-task.txt
codex-night -C ~/project --resume UUID_ДИАЛОГА --approve-for-me
```

Перед пакетным resume закройте другой CLI с этим диалогом. В пределах одного каталога состояния
пакетная/интерактивная обёртка блокирует второй свой запуск для того же workspace или session ID.
`--watch` не приобретает эти locks и не управляет сторонними процессами Codex; не запускайте
параллельно другой CLI для того же задания. Для длительной работы без открытого терминала используйте tmux.

В пакетном режиме терминал показывает сообщения агента и ошибки. `--show-tools` добавляет краткий вывод
инструментов, `--json` выводит исходные JSON-события. Эти параметры не используются с интерактивным TUI.

## Что повторяется

- Только завершённый ход с ошибкой capacity / `server_overloaded`. Упоминание capacity в ответе агента,
  исходном коде или выводе команды не считается ошибкой модели.
- Паузы по умолчанию: 60, 120, 240, 480, затем до 600 секунд с небольшим случайным разбросом.
  Числовой `Retry-After` учитывается, если Codex передал его в ошибке.
- Повторы capacity не ограничены, пока работает CLI. `--max-retries 10` ограничивает их количество;
  `--initial-delay`, `--max-delay`, `--jitter` настраивают ожидание.
- Продолжение просит проверить уже выполненные действия и фоновые команды: само по себе оно
  не даёт права повторно запускать тесты, прошивку или публикацию.

Ошибки авторизации, HTTP 401/403, исчерпанного лимита, контекста и отказа в разрешении не повторяются.
Обёртка не меняет аккаунт или модель, не обходит approvals и не переключает сеть ради повторной попытки.
`--approve-for-me` передаётся только явно и использует штатный автоматический разбор разрешений Codex.

Интерактивный контроль ждёт окончания хода и пустого composer. Он не отправляет Ctrl+C, не трогает
работающий ход и не перезаписывает ручной ввод. Перед отправкой проверяет исходный процесс,
его терминал и открытый журнал сессии. Повтор фиксируется на диске до отправки, чтобы сбой самого
контроля не привёл к повторной отправке той же ошибки. Неопределённое состояние оставляется оператору.
Проверки и ввод через tmux не атомарны относительно одновременных ручных действий. Во время самого
автоповтора не переключайте сессию/foreground job и не вводите текст; при обычном уже видимом draft
watcher ждёт. Для строгой атомарной session-bound доставки нужен отдельный app-server клиент, которого
эта небольшая утилита не реализует.

Успешное завершение и ручное прерывание не вызывают автоматического продолжения. Пакетная обёртка
завершается после задания; интерактивный CLI остаётся открытым для следующего сообщения.

## Состояние и диагностика

```sh
codex-night --status
codex-night --help
```

По умолчанию состояние находится в `~/.local/state/codex-night/`, с учётом `XDG_STATE_HOME`.
`--state-dir` задаёт другой каталог. Каждый запуск сохраняет `status.json`; `latest.json` указывает на последний.
Пакетный режим дополнительно сохраняет JSON-события и stderr каждой попытки. Интерактивный режим читает
штатный rollout самого Codex и сохраняет только состояние контроля. Оно может показать `waiting_capacity`,
`submitted`, `retry_limit`, `monitor_error` или `tui_closed_or_changed`.

Ошибка контроля в `--interactive` не завершает работающий CLI; в терминале появляется предупреждение.
Устраните причину и подключите `--watch`, когда прежний контроллер уже освобождён. Журналы и состояние
доступны владельцу и не предназначены для Git. API-ключи и данные проектов в репозиторий не входят.

## Проверки

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest -v test_codex_night test_interactive
```

Тесты используют подставной CLI и имитацию терминала, без обращений к модели и проектным стендам.
Проверяются повтор с тем же UUID, ожидание, блокировки, прерывание, ошибки доступа, защита ручного ввода
и восстановление состояния контроля. Реальная новая ошибка capacity для проверки искусственно не вызывается.

Официальные документы: [Codex CLI](https://learn.chatgpt.com/docs/developer-commands?surface=cli),
[пакетный режим](https://learn.chatgpt.com/docs/non-interactive-mode).
